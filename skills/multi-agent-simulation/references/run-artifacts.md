# Контракт серии и артефактов

Каждая серия хранит минимальный набор файлов. Названия можно адаптировать под движок, но смысл и связность идентификаторов должны сохраниться.

```text
series/
  scenario.yaml
  manifest.json
  runs/
    <run_id>/
      events.jsonl
      state-summary.json
      status.json
  report.md
```

## `scenario.yaml`

Содержит вопрос, мир до изменения, вмешательства, горизонты, агентов, правила, метрики, источники, допущения, инварианты и стоп-условия.

## `manifest.json`

Содержит идентификатор серии, версию `scenario.yaml`, версию данных, движок, модель, точные промпты и параметры, список сценариев, все `run_id`, зёрна, лимиты, правило агрегации и причину любого сокращения числа прогонов ниже десяти. После первого запуска этот файл не переписывают: изменение создаёт новую серию.

## Файлы прогона

- `events.jsonl` — хронологический журнал событий с временем, участником, действием, входом и результатом.
- `state-summary.json` — итоговые метрики и проверка инвариантов.
- `status.json` — статус `completed`, `failed` или `invalid`, причина, время и потреблённые лимиты.

Не добавляй в `report.md` результаты, для которых нет соответствующего `run_id` и файлов состояния. Исключённые прогоны остаются в манифесте и отчёте с причиной исключения.
