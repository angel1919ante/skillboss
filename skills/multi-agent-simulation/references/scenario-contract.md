# Контракт сценария

Собери эти поля до запуска. Если обязательное поле отсутствует, задача остаётся на этапе постановки.

| Поле | Обязательно | Назначение |
| --- | --- | --- |
| Вопрос решения | Да | Формулирует, чему должен помочь результат. |
| Базовый мир | Да | Описывает исходное состояние без вмешательства. |
| Вмешательство | Да | Одно наблюдаемое изменение для сравнения с базовым миром. |
| Горизонт и шаг времени | Да | Не позволяет смешивать краткий отклик и долгосрочный эффект. |
| Участники и связи | Да | Показывает, через кого может работать механизм. |
| Правила и доступная информация | Да | Ограничивает действия и предотвращает знание будущего. |
| Метрики | Да | Заранее определяет, что будет сравниваться. |
| Источники и даты | Да | Отделяет входные факты от предположений. |
| Допущения | Да | Делает искусственные упрощения проверяемыми. |
| Чувствительные параметры | Если есть | Указывает, какие значения будут варьироваться. |
| Стоп-условия | Да | Определяет момент безопасной остановки. |

## Проверка происхождения

Для каждого значимого факта сохрани ссылку или локальный идентификатор исходника, дату публикации или наблюдения и краткое описание того, что именно подтверждает материал. Не используй непроверенный текст агента как источник факта.

## Минимальная матрица сценариев

| Сценарий | Что меняется | Зачем нужен |
| --- | --- | --- |
| Базовый | Ничего | Точка сравнения. |
| Контрфактический | Один управляемый фактор | Проверка предполагаемого механизма. |
| Стрессовый | Неблагоприятное, но правдоподобное условие | Поиск хрупкости решения. |

Добавляй сценарии только когда они отвечают на отдельный вопрос решения. Комбинации факторов, которые нельзя интерпретировать, не запускай.

## Проверка базового мира

До сравнения вмешательств выбери 2–3 наблюдаемые метрики базового мира. Для каждой зафиксируй источник, наблюдаемое значение, значение модели, способ сравнения и заранее установленный допустимый порог расхождения. Если хотя бы одна критическая метрика не проходит порог, серия остаётся диагностической: не делай из неё выводов о причинном эффекте правила.

## Операционные стоп-условия

Контракт обязан содержать максимальные шаги, время и стоимость серии, допустимую долю ошибочных или пустых прогонов, а также инварианты домена. Например, для рыночной модели это могут быть неотрицательные балансы и отсутствие продаж без покупателя. Нарушение любого порога делает статус серии `invalid`.
